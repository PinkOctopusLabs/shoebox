# Shoebox

A Rust + egui photo library app for macOS. **`docs/SPEC.md` is the source of truth**: read the relevant section before changing behaviour, and flag any conflict rather than silently diverging. For photo editing (the Develop view, raw decoding, export), **`docs/EDITING-SPEC.md`** is the source of truth in the same way; its *Before Phase 1* tasks come first. For iCloud Photos (import, sync, push), **`docs/PHOTOS-SPEC.md`** is, in the same way. Checks that need new photos or a person's eye (deferred gates, real-file verifications) are in **`docs/MANUAL-CHECKS.md`**, a runbook (shot list, gates, checks by area of the app): add new ones to the right section rather than leaving them only in DECISIONS. Known open items, provisional choices and possible enhancements are in **`docs/OPEN-ITEMS.md`**: add to it rather than leaving them only in DECISIONS.

## Layout
- `crates/shoebox-core`: library model, scanning, hashing, duplicate index, SQLite cache, and `fileops` (the only module that moves, renames, copies or writes files; it journals everything). No egui.
  M3: `xmp` (read any form, edit by splicing original bytes), `marks`, `sidecar` (precedence + write planning), `stacks`, `query` (filters, sort, smart filters), `events`, `changes` (unseen-change tracking).
  M4: `review` (duplicate groups for the app, auto-select, decisions → one batch).
  M5: `template` (naming), `import` (plan verified copies), `organise` (stack moves, renames, reject, reference rewrites, filing dated photos out of `_undated/`: `plan_file_dated`), `collections`, `cloud` (cloud-only placeholders: detect, download).
  Dates (SPEC "Dates"): `sidecar::SidecarDate` with a `Precision` (approximate dates as XMP's partial `photoshop:DateCreated`; `sidecar::plan_date`), `Meta::dated` (a sidecar's date over the file's own, which the cache's `exif` rows keep; the sidecar's is cached with the marks), `Catalog::set_dates` (one `sidecar` batch), `dating` (Find dates' clues: other dates in the file, file names, folder names; `dating::Library`: the same frame, iCloud Photos asset or picture (the duplicate finder's cached hashes), the camera's sequence, folder neighbours; picture clues: dates in Vision's text, look-alike and same-people hints from search's embeddings and People, scene hints from search's tags; ranked).
  Develop: `edits` (`.shoebox/edits/<rel>[.<copy>].json`: paths, moves carry them, reattach by size + BLAKE3, catalog working copy vs file, `save_pending` as one `edit` batch).
  Merges: `merges` (photo merges' plan: beside the first source as `<stem>-HDR.dng` (`-Focus.dng`, `-Pano.dng`), never in or from reference folders, sources hashed; the record in `.shoebox/merges.json`, moves rewrite it; `FileOps::add_merge` adds the DNG as one `merge` batch; merges never stack by time or match perceptually).
  M7 (`docs/PHOTOS-SPEC.md`): `photos` (iCloud Photos: `model`, the `PhotoSource` trait (`source`) with `fake::FakeSource` for tests; `ledger`: the sync record in `.shoebox/photos/` (each sync step appends a JSON line an asset to the run's `synced-<run>-<n>.jsonl`, a new one past ~1 MB (`ledger::ROLL_AT`), through fileops' journaled append (`Planned::Append`: a write to a `.jsonl` in `.shoebox`; undo is `Planned::Truncate`); older `synced-<run>-<n>.json` step files still read; newest record wins; `choices.json`); `plan`: what a sync copies; `place`: names (one frame per asset, `-photos` variants for Photos' edits), Photos' date and place into new sidecars when the file lacks them (sidecar dates win over EXIF, `sidecar::SidecarDate`); `sync`: download into the cache, place, copy in steps of one batch (`FileOps::begin_import`/`import_step`/`end_import`); `push`: Send to Photos (what each photo becomes: new asset, edit of the asset it came from, update, or nothing; sends, recorded in `pushed-<run>.json` in a `photos-push` batch (`FileOps::begin_push`); undo in Photos first, refused if the asset changed there since)).
  M6: `timeline` (days, calendar maths, heat levels), `embeddings` (semantic search store + 8-bit exhaustive search + tag rule; own `embeddings.sqlite`, rows by kind), `people` (face rows, grouping, `people.json`).
- `crates/shoebox-decode`: JPEG/TIFF/PNG decoding (`rgb16`: 16-bit TIFFs and PNGs at full precision for Develop), NEF embedded-preview extraction, HEIC, AVIF, WebP and PSD through ImageIO (`heif`: an AVIF's size and rotation from its boxes; WebP's and PSD's sizes from their headers), grayscale thumbnails, `mov` (MOV/MP4 movie headers), `mpeg` (MPG: size and duration from the stream; `movie_info` picks), movie poster frames through AVFoundation (`imageio.rs`; `render_path`). Sony ARW: shown from an embedded JPEG only if it has the whole frame (`arw_previews`; older bodies' are a 16:9 crop), else rendered from the raw data like a DNG (`raw_render`); Develop decodes it with rawler like a NEF.
  NEFs are shown without decoding raw data: `nef.rs` finds the embedded JPEGs and `render()` decodes the smallest big enough (`JpgFromRaw` in the loupe) with zune-jpeg, converts with moxcms and orients. That path (it reads High efficiency NEFs too) stays: it is Develop's instant first paint and the library's thumbnail source. The raw decoder sits beside it in `raw` (rawler, inside `catch_unwind`: Lossless/uncompressed NEFs and DNGs, cropped, black-subtracted, normalised); `nef::compression` reads `NEFCompression` (High efficiency needs a DNG). `examples/raw_probe.rs` shows what it makes of files. DNGs in the library (`dng`): shown from their previews (JPEG or 8-bit RGB, the smallest big enough), else rendered from the raw data by ImageIO (rawler's own developer, `raw::render`, where it can't); the image-data hash is the main image's strips or tiles. A linear DNG (LinearRaw, Shoebox's exports) decodes to three samples a pixel (`RawImage::linear`, with NoiseReductionApplied); `Format::is_raw` is NEF, ARW or DNG.
- `crates/shoebox-develop` (`docs/EDITING-SPEC.md`, being built): the edit pipeline (settings documents, stage cache, wgpu kernels, export). `shoebox-app` calls it; it uses `shoebox-decode::raw` and, for AI stages, `shoebox-ml`. `gpu`: the live pipe as one wgpu compute pass (`develop.wgsl`) on the app's device, tested against `cpu` within 1e-4 (skips without an adapter). `cpu`: the CPU reference pipe (`demosaic` once per file at as-shot WB, then `frame` + `apply`; `cpu::look`: calibration, colour/HSL, Point Color and colour grading in Oklab, black and white, tone-curve tables; `cpu::maps`: dehaze, highlights/shadows, clarity and Smart Lighting (`cpu::smart`: a fast local Laplacian on log luminance at full strength, the slider scaling its gain) as a fast guided filter, coefficients from a 512 px copy cached on the source, evaluated per pixel; `cpu::layers`: local adjustments (per-layer matrix, contrast and the maps' tone gains, blended by masks sampled at the pre-lens source position; the O overlay; per-layer AI strength, sharpening and softening by mixing each source read with `cpu::Aux`'s images, made by `Demosaiced::aux` only when a layer needs them: the source at full and at no AI strength through the detail stage and spots, sharpening's per-pixel fit, softening's change; the GPU's one texture array at binding 10); `cpu::effects`: post-crop vignette and grain on display values (placed by the whole frame; grain from an integer hash both pipes share, sized in full-size pixels); `cpu::detail`: noise reduction, sharpening and texture as one à-trous wavelet stage on Anscombe-stabilised source pixels, noise estimated per image, cached on the source and uploaded as the GPU's source; also local sharpening's change, `Sharpen`, fitted as `alpha·e/(1+beta·e)` from two more runs, and local softening's, `soften`, the finest bands of linear values) (raw stages ported from darktable: RCD, inpaint opposed; then matrix colour, exposure, geometry, display transform, output); `wb`, `colour`: white balance (or, `adaptation: cat16`, colour calibration: the camera's D65 rendering then CAT16 from the illuminant, folded into the colour matrix; layers' tints follow) and colour maths; `examples/develop_probe.rs` renders files. `dcp`: DNG camera profiles from `<data>/profiles/*.dcp` (read only; by name + BLAKE3 in the edit): their matrices replace the file's (`wb::camera_for`), HueSatMap/LookTable in ProPhoto HSV right after the colour matrix (`dcp::Stage`), the optional tone curve in the scene curve's place; all colour tables share the GPU's binding 6. `cube`: looks from `<data>/looks/*.cube` (3D ≤ 65, 1D, shaper; read only, by name + BLAKE3), applied in sRGB after the camera match look with an Amount. `golden`: ΔE2000 comparison with stored renders (`tests/golden.rs`: synthetic goldens in `tests/golden/`; `SHOEBOX_GOLDEN_DIR` runs the real set; `SHOEBOX_GOLDEN_BLESS=1` rewrites them). `benches/pipeline.rs` (criterion) with `examples/bench_check.rs` (fails on a >20% regression against a saved baseline). `lens`: lens corrections as a grid (per-channel source offsets + vignetting gain) from the NEF's own data (`shoebox_decode::nef::lens_data`, IFD 0xC7D5) and Lensfun (`lensfun` crate, bundled DB, loaded once), with a fill zoom folded into the geometry map; `examples/lens_probe.rs` block-matches a raw against its camera JPEG. `export`: presets, Lanczos resize, JPEG/16-bit TIFF/PNG/AVIF, `linear_dng` (the source after demosaic and AI denoise, camera-native, nothing else of the edit), naming, never-overwrite writes (every format also beside the original). `cpu::demosaic` takes a linear DNG past demosaic (as-shot balance and the raw levels only; no hot pixels, highlights, demosaic or AI denoise). `encode`: JPEG with ICC (jpeg-encoder, moxcms); AVIF (rav1e + avif-serialize, not ravif: CICP sRGB or P3, 10-bit, rav1e NEON asm on aarch64); linear DNG (rawler's writer: 16-bit LJPEG LinearRaw, matrices, AsShotNeutral, NoiseReductionApplied); `examples/export_probe.rs` times them on real files. `edit`: the edit document (serde; settings stored as differences from code defaults, unknown modules kept; history as JSON Patches replayed from the defaults, `amend` folds a drag into one step; `render_hash` keys previews and staleness). `denoise`: AI raw denoise (the app registers RawNIND; the mosaic packed RGGB from where red is, the result unpacked and balanced at as shot like RCD's, gain-matched to RCD away from clipping, RCD kept towards clipping; results on disk as half floats, LRU; `Demosaiced::base` blends it in by Strength; `examples/ai_probe.rs` compares it with RCD on a real file). `heal`: spot removal and red-eye on the source after the detail stage (clone, or heal: the copied texture plus the harmonic fill of the edge difference, by SOR; `find_source` by ring similarity), cached and uploaded as the GPU's source via `Demosaiced::prepared`; `heal::remove`: object removal (a spot of brush strokes; the app registers MI-GAN: a crop around them in stored-image units, sRGB-encoded by its own bright end, filled at 512², upsampled and blended by the strokes' feathered coverage, the photo's grain added back; fills by a BLAKE3 of the model's input, in memory, on disk as 16-bit PNGs in `<cache>/ai-fills`, and for the live view on a thread of their own via `maps::Cache::fill`; `examples/remove_probe.rs` on a real raw). `upright`: auto-upright (line segments in a 1024 px upright, lens-corrected copy by gradient-direction region growing; rotation and Transform perspective by grid then pattern search; Auto, Level, Vertical, Full). `mask`: local adjustment masks (recipes in the edit: gradients, ellipses, brush strokes, luminance and colour ranges, in long-edge units of the stored image; rasterised to 8-bit on a ≤2560 px grid, cached on the source; AI parts (Subject, People, Face parts, Object, Landscape: Sky, Vegetation, Water, Mountains, Buildings, Ground) from finders the app registers with an identity (landscape's give coarse probabilities, which `mask::landscape` upsamples to the picture by the colour guided filter); `mask::store`: what they find kept as 8-bit PNGs in `<cache>/ai-masks`, keyed by a BLAKE3 of the exact picture shown them, the kind, clicks and identity, LRU; `mask::fine`: for sources larger than the grid with AI parts (exports, 100% regions), every layer on the source's pixels within 128 MB, AI parts upsampled by a colour fast guided filter, geometric parts rasterised there, ranges bilinear). `depth`: Lens Blur's depth maps (a registered model's output on the picture as shown, normalised, kept by `mask::store` as 16-bit PNGs, upsampled by the colour guided filter, `mask::guided`; per source, found as subjects are). `cpu::lens_blur`: Lens Blur in the source stage (circle of confusion from refined inverse depth, a working copy of at most 1024 px gathered as if scattered in a back and a front layer, mixed back per source texel; circle or six blades, highlight boost; local adjustments' Depth refines the map); the GPU's two passes in `gpu/lens_blur.wgsl` (bindings 11–12 of the develop pass). `volume`: volume deformation (ViewPoint's wide-angle fix: cylindrical or stereographic by Amount from the focal length, and per-face stereographic patches feathered in, Shih et al. 2019 simplified; boxes kept in the edit), folded into the lens grid after lens corrections and before the perspective (`lens::grid_with`). `merge`: photo merges (DECISIONS "Photo merges: groundwork"; sources read by `merge::load` as camera-native linear at the code defaults, upright, clipped pixels marked; `merge::align`: Harris corners + MOPS-like descriptors + ratio-tested matches + RANSAC (translation, similarity, affine, homography), then a direct Gauss–Newton refinement with gain and offset, coarse to fine, and Catmull–Rom `warp`; `merge::hdr`: HDR (inverse-variance weights, exposure measured from the pixels, deghosting against the middle exposure, streamed a frame at a time); `merge::focus`: focus stacking (DECISIONS "Focus stacking"; 2+ frames streamed, each aligned to its neighbour towards the middle one by a similarity, composed; Pyramid: Laplacian coefficients by a steep soft maximum of local energy over noise, averaging where none is sharper, clamped to the frames' range; Depth map: whole pixels by smoothed fine-detail energy; cut to what every frame covers; `examples/focus_probe.rs` times 10 × 24 MP); `merge::pano`: panorama (each frame's `lens` grid folded into its one resample; all pairs matched and refined on the pixels; a turning camera's rotations and one focal length bundle adjusted (`pano::bundle`: Levenberg–Marquardt, Huber), or frames laid flat on a plane; wave-corrected; gains from the overlaps; `pano::project`: Spherical, Cylindrical, Perspective; `pano::seam`: centre-weighted seams then graph cuts (Dinic) on a ~1 MP canvas, the largest inner rectangle; `pano::blend`: multi-band blending, frames read again one at a time; at most 150 MP; `examples/pano_probe.rs` times 6 × 24 MP); `merge::dng` + `encode::float_dng`: a half-float LinearRaw DNG (deflate, predictor 3, WhiteLevel 1) with the reference's colour and EXIF (no sub-seconds), previews and an XMP record of the sources; `examples/merge_probe.rs` times 3 × 24 MP). `dng`: High efficiency NEFs → Adobe DNG Converter (`-c -p0`, two at once, 180 s timeout) → `<cache>/dng/<blake3 of NEF>.dng`, LRU-evicted; tests use a shell-script converter, and `--ignored` runs the real one on the real fixture.

## Building the app
- `scripts/bundle-macos.sh` → `target/release/bundle/Shoebox.app` (+ zip). Ad-hoc
  signed by default; `SIGN_IDENTITY="Developer ID Application: …"` and
  `NOTARY_PROFILE=<notarytool profile>` for a notarized build.
- To try a build without touching real settings: `SHOEBOX_DATA_DIR=<scratch dir>`.
- Updates: `scripts/fetch-sparkle.sh` (pinned, checksummed Sparkle) is embedded
  when `assets/sparkle-public-key.txt` exists. `scripts/release-macos.sh <version>`
  publishes a signed, notarized release + appcast to GitHub Releases.
  `SHOEBOX_UPDATE_FEED=<url>` points a build at a test feed and checks at once;
  test with throwaway builds (`BUNDLE_ID=…updatetest`, a test key via
  `SPARKLE_PUBLIC_KEY`), never the real app.

## Working rules
- One milestone at a time, in order, each as a reviewable chunk.
- Before finishing any task: `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.
- `target/` grows without bound (Cargo keeps every old build; macOS keeps debug info in each `.o`): a clean build with all tests is about 7 GB and 3 minutes, so `cargo clean` once it passes about 30 GB. `cargo sweep --time` doesn't work here (macOS access times are unreliable, so it deletes current builds). Agent worktrees build with `CARGO_INCREMENTAL=0` and are `cargo clean`ed once merged.
- `thiserror` in library crates, `anyhow` in binaries. No `unwrap()`/`expect()` outside tests (enforced by workspace clippy lints).
- No `unsafe` except in thin FFI wrappers (`shoebox-core/src/fileops/sys.rs`, `shoebox-decode/src/imageio.rs`, `shoebox-ml/src/vision.rs`, `shoebox-photos/src/sys.rs`, and the app's `display.rs`, `platform.rs`, `updater.rs`, `menu.rs`, `video.rs`).
- `shoebox-core` must not depend on egui. Every file operation goes through `shoebox_core::fileops`.
- Target `aarch64-apple-darwin`, toolchain pinned in `rust-toolchain.toml`, minimum macOS 27, release `lto = "thin"`.
- **macOS only for now; Linux is deferred** (decided 2026-10-22). Build,
  test and design for macOS; new work needs no Linux branch, and there's no
  local Linux check before commits. Existing `cfg` Linux branches stay, and
  CI's Linux job (GitHub Actions, public repo PinkOctopusLabs/shoebox) is
  disabled (`if: false`) until Linux comes back. When it does (DECISIONS,
  "Linux deferred"), the Docker check was:

## Safety rules (hard requirements)
1. Never delete files outside the app's own cache directories. "Remove" means move to `_rejected/`/`_duplicates/`, or the macOS Trash on explicit command.
2. Journal every move, rename and copy, with a batch id, *before* it runs.
3. Never write to image files that are already there: originals are never modified or replaced. Marks go to XMP sidecars; Shoebox's own files and photo edits go in `<root>/.shoebox/**/*.json`. Shoebox may add *new* files to a library (imports, exports the person sends there, and photo merges: an HDR, panorama or focus stack the person makes from photos they chose, written beside its sources as a new DNG), always through `fileops`: journaled, verified, undoable, never replacing a file. A merge reads its sources only: it never changes, moves or hides them, and it is refused in reference folders.
4. Never overwrite: collisions get `-1`, `-2` suffixes. The one exception: an export outside the library may replace an earlier file when the person chooses Replace when asked; it's written beside it first, then renamed over it. Inside the library an export replaces only the earlier export it redoes (re-exporting a stale one, on the person's click): the new file is written and verified in the cache first, then one journaled batch moves the old file to the Trash and copies the new one into its place, so ⌘Z restores it. Nothing else in the library is ever replaced.
5. Reference roots are read-only.
6. Multi-file operations show a dry-run table and need confirmation.
7. **Never run anything against the real photo library during development.** Use fixtures or an APFS clone (`cp -cR Photos Photos-test`).
8. **Photos (iCloud Photos) is written only by an explicit push**, with a dry-run table and confirmation: add an asset, add or replace Shoebox's own edit, or undo a push. Nothing else in Photos is changed.
9. **No PhotoKit against the person's Photos library during development.** PhotoKit only opens the system library, so real PhotoKit code runs only in a separate macOS user account with a test library from fixtures; everything else uses `photos::fake::FakeSource`.
